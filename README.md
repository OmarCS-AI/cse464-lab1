# Capstone Git Workflow Practice

This repository is a small, original practice project for learning a professional Git/GitHub workflow.

## Project goal
The goal is to organize a simple capstone task tracker while practicing version-control habits used on software teams: clear commits, feature branches, pull requests, reviewable changes, and documentation.

## Repository structure
- `README.md` - project purpose and workflow summary
- `docs/workflow.md` - notes on the Git workflow used
- `tasks.md` - a small capstone-style task tracker

## Workflow practiced
1. Start from the `main` branch.
2. Create a separate feature branch.
3. Make focused commits with descriptive messages.
4. Open a pull request to review the changes.
5. Merge the approved work back into `main`.

## Why this matters
Using branches and pull requests keeps unfinished work separate from the stable branch, creates a visible history of decisions, and makes collaboration easier when multiple people contribute to the same project.
